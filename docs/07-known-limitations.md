# محدودیت‌های شناخته‌شده و کارهای باقی‌مانده

این سند صادقانه فهرست می‌کند چه‌چیزی واقعی است، چه‌چیزی آزمایشی، و چه‌چیزی هنوز ساخته نشده.
طبق تصمیم صریح ابتدای پروژه، این نشست روی فاز ۱ تا ۳ (زیرساخت، صفحه‌ساز، خرید و دسترسی
ویدئو) تمرکز کامل داشت.

## اتصال‌های آزمایشی (نه واقعی)

- **پرداخت**: فقط `PAYMENT_PROVIDER=mock` تست شده. adapter زرین‌پال نوشته و طبق مستندات
  رسمی پیاده‌سازی شده اما بدون merchant_id واقعی هرگز فراخوانی نشده.
- **پیامک**: فقط `SMS_PROVIDER=mock` تست شده (پیام در لاگ سرور چاپ می‌شود). adapter
  کاوه‌نگار نوشته شده اما بدون API key واقعی فراخوانی نشده.
- OTP در پاسخ API فقط وقتی `ALLOW_OTP_DEBUG_RESPONSE=true` (پیش‌فرض false) و
  `NODE_ENV!==production` برگردانده می‌شود — برای آزمون خودکار Playwright.

## فاز ۴ (دوره حضوری/مخاطبان/ارتباطات) — پایه، نه کامل

ساخته‌شده: مدل داده کامل، رزرو موقت ایمن در برابر race (compare-and-swap روی
occupiedCount)، آزادسازی خودکار رزرو منقضی، فهرست انتظار و اطلاع‌رسانی آن، worker صف پیام
با کلید یکتا (بدون ارسال تکراری)، محاسبه سالگرد تولد شمسی با رفتار مشخص برای ۳۰ اسفند.

**ساخته‌نشده / رابط اختصاصی ندارد**:
- رابط کاربری اختصاصی برای ساخت/تأیید کمپین در پنل (فعلاً از CRUD پیش‌فرض Payload برای
  کالکشن `Campaigns` استفاده می‌شود؛ پیش‌نمایش شمار مخاطب پیش از ارسال پیاده نشده).
- تقویم شمسی اختصاصی در فرم انتخاب تاریخ نوبت دوره حضوری (فعلاً از date-picker میلادی
  پیش‌فرض Payload استفاده می‌شود؛ نمایش عمومی سایت شمسی است، اما فرم ورود تاریخ در پنل نه).
- داشبورد گزارش فروش/بازدید (بخش ۱۲ سند) — فقط داده خام از طریق CSV export (`/api/admin/export/*`)
  و کوئری مستقیم در پنل در دسترس است؛ ویجت آماری اختصاصی ساخته نشده.

## فاز ۵ (آزمون/مستندات) — حداقلی، نه گسترده

- آزمون‌های واحد (`npm run test:unit`): منطق خالص (پول، موبایل، تاریخ شمسی/تولد، CSV).
- آزمون‌های یکپارچگی (`npm run test:integration`، نیاز به Postgres واقعی): OTP، تأیید
  پرداخت و idempotency، دسترسی درس خصوصی، ظرفیت دوره حضوری هم‌زمان، کد تخفیف.
- Playwright: یک تست کامل مسیر خرید (`purchase-and-watch.spec.ts`) و یک smoke test ورود
  مدیر (`admin-page-builder.spec.ts` — نیازمند `E2E_ADMIN_EMAIL/PASSWORD`، بدون آن رد
  می‌شود). **تست کامل «جابه‌جایی بلوک و بازگرداندن نسخه» به‌صورت Playwright نوشته نشده** —
  چون تعامل drag-and-drop با UI پویای Payload بدون امکان اجرا/مشاهده واقعی، احتمال
  شکنندگی بالایی داشت؛ این مسیر باید دستی طبق `docs/03-panel-guide-fa.md` آزمایش شود.
- نتیجه واقعی اجرای این آزمون‌ها (و typecheck/lint/build) در
  [۰۸-acceptance-report.md](./08-acceptance-report.md) ثبت شده.
- backup/restore: دستورات مستند شده‌اند اما آزمون بازیابی واقعی در این نشست روی داده واقعی
  اجرا نشده (نیاز به دیتابیس در حال اجرا با داده واقعی دارد).
- پایپ‌لاین CI/CD ساخته نشده.

## محدودیت‌های فنی شناخته‌شده

- **rate limit** (`src/lib/rate-limit.ts`) در حافظه پردازه است؛ اگر اپ روی چند نمونه/replica
  اجرا شود، هر نمونه محدودیت جدا دارد. برای مقیاس افقی باید به فروشگاه مشترک (جدول
  دیتابیس یا Redis) منتقل شود.
- **یکتایی (student, lesson) در LessonProgress**: در سطح دیتابیس اعمال نشده (Payload از
  unique ترکیبی چندفیلدی declarative پشتیبانی ساده‌ای ندارد)؛ به‌جای آن همیشه از
  `src/lib/progress/upsert-progress.ts` (find-then-update-or-create) استفاده می‌شود. اگر
  در آینده مستقیم به کالکشن نوشته شود، این ریسک وجود دارد.
- **پخش ویدئو**: فقط MP4 مستقیم با پشتیبانی HTTP Range (seek کار می‌کند). استریم تطبیقی
  (HLS/DASH) و تبدیل/فشرده‌سازی خودکار ویدئو پیاده‌سازی نشده.
- **جلوگیری از دانلود ویدئو**: `controlsList="nodownload"` فقط دکمه دانلود مرورگر را پنهان
  می‌کند؛ ادعای جلوگیری کامل از دانلود یا ضبط صفحه نشده و چنین چیزی هم فنی ممکن نیست.
- **قالب Jalali در فرم پنل**: فیلد تاریخ نوبت دوره حضوری در پنل با تقویم میلادی پر می‌شود
  (نمایش عمومی در سایت شمسی است).
- **eslint/typecheck/build/test واقعاً اجرا شد یا نه**: نتیجه دقیق در
  [۰۸-acceptance-report.md](./08-acceptance-report.md).

سارا جایگزین شوند.
