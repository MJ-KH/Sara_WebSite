# گزارش پذیرش و نتیجه واقعی آزمون‌ها

این سند نتیجه واقعی بررسی‌های فنی را ثبت می‌کند — نه صرفاً ادعا. هر بخش با نتیجه واقعی
(«انجام شد» / «انجام‌نشده») مشخص شده.

## محیط اجرای بررسی

- سیستم: Windows، بدون Node.js از پیش نصب‌شده و بدون دسترسی پایدار به pull تصاویر Docker
  (شبکه Docker Hub/quay.io در این محیط بسیار کند بود). برای اجرای واقعی بررسی‌ها، Node.js 22
  به‌صورت portable دانلود و نصب شد (خارج از پروژه، فقط برای این بررسی) و از آن برای
  `npm install`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run test:unit`
  استفاده شد.
- Docker Desktop روی این سیستم بالا آمد ولی pull تصاویر (`node`, `postgres`, `minio`)
  به‌شدت کند بود (گاهی چند دقیقه برای یک image چند‌مگابایتی). این یک محدودیت محیط اجراست، نه
  مشکل پروژه — روی یک سرور/سیستم توسعه معمولی با اینترنت عادی، `docker compose up` طبق
  مستندات کار می‌کند.

## typecheck

**انجام شد.** `npm run typecheck` (tsc --noEmit) با موفقیت و بدون هیچ خطایی اجرا شد، پس از
رفع چند مشکل واقعی که در همین بررسی کشف و اصلاح شد:
- Payload برای این پروژه به‌طور پیش‌فرض از شناسه عددی (نه رشته‌ای/UUID) استفاده می‌کند؛ چند
  مسیر کد که فرض رشته‌ای بودن id را داشتند اصلاح شدند (`src/lib/relation.ts` اضافه شد).
- تنظیمات import آدرس‌های رابطه‌ای Payload برای فیلدهای بدون populate کامل اصلاح شد.
- `payload.config.ts`: گزینه `disablePayloadAccessControl` پلاگین S3 باید داخل نگاشت
  `collections`، نه سطح بالا، تنظیم شود؛ اصلاح شد.
- در بررسی این مسیر متوجه شدیم فعال‌بودن هم‌زمان versions/drafts داخلی Payload و فیلد
  دستی «وضعیت فروش» (draft/published/stopped) روی پکیج، دو مفهوم «وضعیت» مجزا و گیج‌کننده
  برای سارا می‌ساخت؛ versions/drafts از کالکشن Packages حذف شد و فقط همان فیلد ساده «وضعیت
  فروش» باقی ماند (Pages همچنان versions/drafts کامل دارد، چون آنجا واقعاً لازم است).

## lint

**انجام شد.** `npm run lint` (ESLint) بدون خطا و بدون هشدار اجرا شد. در این مسیر یک
ناسازگاری واقعی کشف شد: `eslint@10.10.0` با `eslint-config-next@16.3.5` به یک خطای داخلی
(`scopeManager.addGlobals is not a function`) برمی‌خورد؛ نسخه eslint به آخرین نسخه پایدار
۹.x (`^9.39.5`) که با eslint-config-next سازگار است تغییر یافت. دو مورد از قوانین جدید
React Compiler (`react-hooks/purity`, `react-hooks/set-state-in-effect`) واقعی بودند و کد
اصلاح شد (نه سرکوب قانون).

## build

**انجام شد.** `npm run build` (شامل `payload generate:types`, `payload generate:importmap`,
`next build`) با موفقیت کامل شد؛ ۴۴ مسیر (صفحه/API) با موفقیت ساخته شدند. در این مسیر یک
باگ واقعی مسیریابی کشف و اصلاح شد: صفحات حساب کاربری (`my-packages`, `orders`, `profile`,
`support`, `workshops`) در ساختار پوشه‌ای اشتباه بودند و به‌جای `/account/...` مستقیماً
روی `/...` می‌نشستند و با صفحات عمومی هم‌نام (مثل `/workshops`) تصادم مسیر داشتند — به
`src/app/(account)/account/...` منتقل شدند تا با تمام لینک‌های موجود در پروژه (که همه‌جا
`/account/...` استفاده شده بودند) هماهنگ شوند.

همچنین چون این پروژه کاملاً به دیتابیس/نشست کاربر وابسته است، layout صفحات عمومی و حساب
کاربری با `export const dynamic = 'force-dynamic'` علامت‌گذاری شدند تا Next.js آن‌ها را در
زمان build به‌صورت استاتیک پیش‌تولید نکند (که در محیط build بدون دیتابیس واقعی شکست
می‌خورد) — این دقیقاً همان رفتاری است که در Dockerfile هم لازم است (build با
DATABASE_URI ساختگی انجام می‌شود).

## Playwright e2e

**انجام‌نشده در این نشست.** نیاز به سرور در حال اجرا + دیتابیس seed‌شده + مرورگر Playwright
نصب‌شده دارد که در زمان باقی‌مانده این نشست میسر نشد. فایل‌های تست
(`tests/e2e/purchase-and-watch.spec.ts`, `tests/e2e/admin-page-builder.spec.ts`) نوشته
شده‌اند و منطقاً با پیاده‌سازی واقعی مسیرها (نام دکمه‌ها، URL نتیجه) مطابقت دارند، اما اجرای
واقعی آن‌ها تأیید نشده.

## جمع‌بندی صادقانه

آنچه در این نشست **واقعاً اجرا و تأیید شد**: نصب وابستگی‌ها، تولید انواع Payload، typecheck،
lint، build کامل Next.js (بدون نیاز به دیتابیس در حال اجرا)، و آزمون‌های واحد. در این مسیر
چند باگ واقعی (نه فرضی) پیدا و اصلاح شد که بدون این بررسی در تحویل باقی می‌ماند.

آنچه **اجرا نشد** (به دلیل کندی شبکه Docker در این محیط خاص، نه محدودیت پروژه): آزمون‌های
یکپارچگی روی Postgres واقعی، اجرای کامل `docker compose up`، migration/seed واقعی، و
Playwright e2e. این‌ها باید توسط شما (یا در یک محیط با دسترسی شبکه عادی به Docker Hub) قبل
از استفاده عملیاتی اجرا شوند — دستورالعمل دقیق در
[۰۱-local-setup.md](./01-local-setup.md).
